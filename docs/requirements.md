# 要件定義書：InquiryManagement（問い合わせ管理アプリ）

## 背景・目的

本アプリは、以下を達成することを目的として開発する。

- 先に取り組んだ[TaskManagement](https://github.com/takahiromorikawa/TaskManagement)とは異なる技術スタック（Ruby on Rails + Vue.js + MySQL）で、
  同様の開発フロー（要件定義から設計・実装・動作確認まで）を経験すること
- TaskManagementでは扱わなかった**1対多のリレーション**（1件の問い合わせに対する複数件の返信）を伴うデータ設計・実装を経験すること
- TaskManagementでは扱わなかった**認証機能**（担当者ログイン）を伴う設計・実装を経験すること

そのため、機能は必要最小限（MVP）に絞る。担当者は「管理者」と「一般担当者」の2種類のみとし（担当者の追加は管理者だけが行える）、それ以上のロール・権限管理や、複数担当者へのアサインといった発展的な機能は今回のスコープ外とする。

## 非機能要件

本番運用水準は求めず、以下の方針とする。

| 分類 | 要件 | 補足 |
|---|---|---|
| 性能 | 一覧表示は体感1秒以内 | 問い合わせ件数は100件程度までを想定した上での目安。負荷試験は行わない |
| 可用性 | SLAは定めない | ローカル環境での動作を前提とし、常時稼働は求めない |
| セキュリティ | 担当者ログイン（セッション認証）を実装。権限は「管理者」「一般担当者」の2種類のみで、区別するのは担当者の追加操作だけ | 外部公開はせず、ローカル環境限定での利用を前提とする。HTTPS化・CSRF対策等の本番向け対策は最小限に留める |
| データ永続化 | MySQLを使用（ローカルはDocker等で起動） | アプリケーション再起動後もデータは保持される。バックアップ・リストア機能は持たない |
| 保守性 | Railsの標準的なMVC構成（APIモード）に従う | Vue側は別リポジトリ構成とせず、同一リポジトリ内の別ディレクトリで管理する |
| 動作環境（バックエンド） | Ruby on Rails（APIモード） | 確定したバージョンは[技術スタック](tech-stack.md)に記載（Ruby 3.3.9 / Rails 7.1） |
| 動作環境（フロントエンド） | Google Chrome最新版で動作確認 | 他ブラウザでの動作保証はしない |
| ログ | コンソール出力のみ | 外部ログ基盤との連携は行わない |
| 画面表示 | PCデスクトップ画面を基本とする | レスポンシブ対応は今回のスコープ外とする |

各ドキュメントの全体像は[画面仕様](screens.md)を参照。
