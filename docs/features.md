# 機能要件：InquiryManagement

## 機能一覧（MVP）

問い合わせの投稿は顧客（ログイン不要）、それ以外の操作は担当者（ログイン必須）が行う。

| 機能 | 内容 | 利用者 |
|---|---|---|
| 問い合わせ投稿 | 会社名・氏名・メールアドレス・件名・内容を入力して問い合わせを送信する | 顧客（ログイン不要） |
| 担当者ログイン | メールアドレス・パスワードでログインする | 担当者 |
| 問い合わせ一覧取得 | 登録されている全問い合わせを取得する | 担当者 |
| 問い合わせ詳細取得 | IDを指定して1件の問い合わせと、それに紐づく返信一覧を取得する | 担当者 |
| 返信投稿 | 問い合わせに対して返信を投稿する（1件の問い合わせに複数件の返信が紐づく） | 担当者 |
| ステータス変更 | 問い合わせのステータス（未対応／対応中／対応済み）を変更する | 担当者 |
| ログアウト | ログインセッションを終了する | 担当者 |

以下は今回のスコープ外（将来的な拡張候補）とする。

- 問い合わせの削除
- 担当者ごとのアサイン（誰が対応するかの割り当て）
- ロール・権限管理（担当者間での権限の区別）
- 顧客向けログイン・マイページ（自分の問い合わせ状況を確認する画面）
- ファイル添付
- メール通知（新規投稿時・返信時の通知）
- レスポンシブ対応（スマートフォン・タブレット表示）

## ユースケース・操作フロー

### UC1: 問い合わせを投稿する

- アクター: 顧客（ログイン不要）
- 事前条件: 問い合わせフォーム画面（S1）を開いている
- 基本フロー:
  1. 会社名・氏名・メールアドレス・件名・内容を入力する
  2. 「送信」ボタンを押すと問い合わせが登録される。ステータスは自動的に「未対応」になる
  3. 送信完了メッセージが表示される
- 代替フロー:
  - いずれかの項目が未入力の場合、送信せずエラーメッセージを表示する

### UC2: 担当者としてログインする

- アクター: 担当者
- 事前条件: ログイン画面（S2）を開いている
- 基本フロー:
  1. メールアドレス・パスワードを入力し、「ログイン」を押す
  2. 認証に成功すると、問い合わせ一覧画面（S3）に遷移する
- 代替フロー:
  - メールアドレス・パスワードの組み合わせが誤っている場合、ログインせずエラーメッセージを表示する
  - 未ログインの状態でS3以降の画面に直接アクセスした場合、ログイン画面（S2）にリダイレクトする。
    その後ログインに成功すると、元々アクセスしようとしていた画面に戻る（それ以外は一覧画面へ）

### UC3: 問い合わせ一覧を確認する

- アクター: 担当者（ログイン済み）
- 事前条件: なし
- 基本フロー:
  1. 問い合わせ一覧画面（S3）を開く
  2. 全問い合わせが、件名・送信者・ステータス・受信日時とともに一覧表示される
  3. 一覧から対象の問い合わせをクリックすると、詳細画面（S4）に遷移する

### UC4: 問い合わせ詳細と返信スレッドを確認する

- アクター: 担当者（ログイン済み）
- 事前条件: 表示対象の問い合わせが存在する
- 基本フロー:
  1. 問い合わせ詳細画面（S4）を開く
  2. 問い合わせ本文（会社名・氏名・メールアドレス・件名・内容）が表示される
  3. それまでの返信が、投稿日時の古い順にスレッド形式で表示される

### UC5: 返信を投稿する

- アクター: 担当者（ログイン済み）
- 事前条件: 対象の問い合わせが存在する
- 基本フロー:
  1. 問い合わせ詳細画面（S4）の返信フォームに本文を入力する
  2. 「返信する」ボタンを押すと、返信スレッドの末尾に新しい返信が追加される
  3. 返信を投稿した担当者の名前が、返信とともに表示される
- 代替フロー:
  - 本文が未入力の場合、送信せずエラーメッセージを表示する

### UC6: 問い合わせのステータスを変更する

- アクター: 担当者（ログイン済み）
- 事前条件: 対象の問い合わせが存在する
- 基本フロー:
  1. 問い合わせ詳細画面（S4）のステータス選択欄で「未対応／対応中／対応済み」のいずれかを選ぶ
  2. 選択した時点でステータスが更新される
- 補足:
  - ステータスの前後関係による制約はない（対応済みから未対応に戻すことも可能）

### UC7: ログアウトする

- アクター: 担当者（ログイン済み）
- 基本フロー:
  1. 画面上部の「ログアウト」ボタンを押す
  2. ログインセッションが終了し、ログイン画面（S2）に遷移する

### 全体の操作フロー（概略）

```
顧客: 問い合わせフォーム（S1） → 送信 → 問い合わせ登録（未対応）

担当者: ログイン（S2/UC2）
   │
   ├─ 問い合わせ一覧（S3/UC3）
   │        │
   │        └─ クリック → 問い合わせ詳細（S4/UC4）
   │                          ├─ 返信を投稿（UC5） → スレッドに追加
   │                          └─ ステータスを変更（UC6）
   │
   └─ ログアウト（UC7） → ログイン画面へ
```

各ユースケースの画面上の操作対象は[画面仕様](screens.md)、バックエンドとのやり取りは[API仕様](api.md)を参照。
